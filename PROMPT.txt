我在一家做偏振光学器件的公司做应用支持。客户常问：「我这串波片、偏振片按这个角度摆，出来是什么偏振态，能透过多少光？」我们现在靠一个老桌面小工具，只能算完全偏振光，算错了也看不出来。想做一个网页版的偏振光路计算器，销售和客户都能用。

光路是一串按顺序排列的元件，每个元件有类型和参数：理想线偏振片（透光轴方位角）；实际偏振片（主透过率与消光比）；任意延迟量的线性波片（快轴方位角、延迟量，四分之一波和半波给快捷选项）；旋光片（旋转角）；部分退偏器（退偏度）。入射光可以是完全偏振光（Jones 矢量，或方位角加椭圆率），也可以是部分偏振光（Stokes 矢量）或自然光。完全偏振且光路中没有退偏元件时，服务同时用 Jones 矩阵和 Mueller 矩阵两套方法计算，两者给出的出射 Stokes 必须一致，误差 1e-12 以内；存在退偏或部分偏振输入时只走 Mueller。输出出射 Stokes 矢量、偏振度、方位角、椭圆率、旋向、相对入射的透过率，以及每经过一个元件后的中间态。

下面这些物理关系要被测试钉住：两个透光轴正交的理想偏振片透过率为零，中间插一个 45° 偏振片后自然光透过率为 1/8；线偏光过偏振片服从马吕斯定律 cos²θ；快轴方位 φ 的半波片把方位角 α 的线偏光变成方位角 2φ−α 的线偏光；快轴 45° 的四分之一波片把水平线偏光变成圆偏光，两片串联等效一片半波片；整条光路绕光轴整体转一个角度，出射态方位角随之转同一角度、透过率不变；波片、旋光片这类无损元件不改变光强与偏振度；任何物理可实现的光路，出射 Stokes 都满足 S0 ≥ √(S1²+S2²+S3²)。另有反向求解：给入射态和目标出射态，在一片波片的快轴角（可选连同延迟量）上搜索，使出射态与目标在庞加莱球上的距离最小，报告最优参数与残差。

网页左侧是元件列表，可添加、删除、上下调整顺序、修改参数，改完右侧立即刷新；右侧显示庞加莱球（二维投影或三维都行，画出入射态、逐元件的中间态轨迹和出射态）、偏振椭圆示意和数值表。光路方案可以命名保存、重新打开、复制成新方案，存在服务端数据库。所有计算在后端完成，前端只负责展示与编辑。

输入校验：方位角不是有限数、消光比不在 (0,1]、退偏度超出 [0,1]、Stokes 矢量不满足 S0 ≥ 偏振部分模长、空光路，前后端都要给出明确提示。

服务端框架选 Fastify，TypeScript 编写，运行时 Node.js 20，方案存 SQLite；前端 Vue 3 + Vite + TypeScript，三维可视化库自选。复数与矩阵运算、元件模型、Jones 与 Mueller 两套传播、反向求解、方案存储、路由，以及前端的元件编辑、庞加莱球、数值面板、API 客户端，分别放在不同的模块和文件里。后端测试覆盖上面每条物理关系，前端给元件参数校验写单测。交付时附 compose：后端单独一个容器、前端构建后交给 nginx 托管，SQLite 数据卷挂在后端上。
